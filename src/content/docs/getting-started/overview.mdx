nSealr develops open-source Nostr signing devices and the software needed to
use them. The first milestone covers a connected ESP32-S3 without a secure
element or persistent identity vault, and independent Raspberry Pi and
ESP32-P4 offline session signers.

The shared Rust engine owns Nostr signing semantics. Bridge, CLI, service,
client/browser integration and the TypeScript SDK connect the user workflow.
The host prepares requests and verifies responses for a separately selected
identity. It cannot replace device review or grant physical approval.

## Current source and evidence

Start at [nSealr/nsealr](https://github.com/nSealr/nsealr), which owns device
apps, host packages, contracts and the public task graph. Selected companion,
raspberry and specs sources have migrated there. Original repositories remain
history; they are not separate current installation prerequisites.

Public-fixture signatures and physical approval/rejection traces exist for
the S3 and P4 development paths. They do not establish entropy quality,
custody, recovery, offline state, complete interoperability or a device release.
Pi image/adapters and its assembled-device workflow have separate gates.
There is no production-ready signer for real identities advertised here.
