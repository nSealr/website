This is a developer entry point, not installation of a qualified device
release. Use public fixtures only. No hardware, private repository or
production identity is needed for the software checks.

## Public source

```sh
git clone https://github.com/nSealr/nsealr.git
cd nsealr
python3 tools/baseline/bootstrap.py /absolute/absent/runtime
python3 /absolute/absent/runtime/nsealr/tools/baseline/run.py /absolute/absent/runtime
```

Choose a new absolute destination on Linux x86_64/glibc. The pinned bootstrap
rejects destination reuse and dirty/drifting source. Read its
[public guide](https://github.com/nSealr/nsealr/tree/main/tools/baseline) for
prerequisites, exact dependency pins, network requirements and limits.
The complete run records actual commands and failures; it is not a five-minute
device installation promise.

The product checkout contains `apps/bridge`, `packages`, `apps/pi`, device
apps and the authoritative `protocols/contracts/v1` artifact. Do not clone
companion, raspberry or specs as live sibling dependencies.

## Inspect the retained CLI

From the prepared runtime's product checkout, with its tool environment:

```sh
pnpm nsealr --help
pnpm nsealr verify-response \
  --request protocols/contracts/v1/examples/request-kind-1-basic.json \
  --response protocols/contracts/v1/examples/response-kind-1-basic.json
```

This verifies an existing public fixture's request binding, canonical event ID
and signature. It does not create a signature, prove device approval, discover
an identity or independently select the expected user's key. A real round trip
also needs the admitted profile, separate expected-key pin, current local
grants, actual transport lifecycle and physical review.

## Before using a device

Use the current [product requirements](https://github.com/nSealr/nsealr/tree/main/docs/product)
and the exact app/qualification evidence linked by the
[task graph](https://github.com/nSealr/nsealr/blob/main/plan/work-items.json).
Development binaries and public-fixture paths are not supported release
installers. Board association, entropy, session recovery and physical limits
remain profile-specific. Browser installation and live-client compatibility
need their own named evidence.

No real identity, seed import, hardware flash or automatic device reset is part
of this quickstart.
