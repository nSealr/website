The first milestone is a usable client-to-device-to-verified-response workflow
for three independently qualified device paths.

<SystemMap />

| Initial path | Intended profile | Current limitation |
| --- | --- | --- |
| ESP32-S3 | Connected USB, physical review, no SE or persistent identity vault | Public-fixture round trips exist; session custody, recovery, entropy and interface lifecycle still need release qualification. |
| Raspberry Pi | Offline QR, session custody; reload after power loss | Image/adapters and the assembled-device workflow have separate physical gates. |
| ESP32-P4 | Offline camera/display QR, session custody; reload after power loss | Public-fixture signing exists; complete manual host use and offline conditions remain under qualification. |

Connected/offline describe interaction, not a security ranking. USB-only S3
does not require a battery. Offline Pi/P4 prerequisites do not establish radio
absence merely because a host flag says so.

## Shared ownership

[nSealr/nsealr](https://github.com/nSealr/nsealr) owns the portable normative Rust
engine, device apps, Bridge/CLI/service/client/browser packages, the TypeScript
SDK, contracts and the sole task graph. Host software has no identity custody
or device-approval authority. Reference oracles and test-only software signers
are development tools, not a second production engine.

Local service authorization, expected-user binding, bounded transport,
cancellation, retry/reconnect and response verification are part of the usable
workflow. An API helper or valid signature alone does not qualify that workflow.

## Future work preserved

Custom Board and its Nostr-free embedded Board SDK remain separate future
work and are not prerequisites for the three initial devices. That embedded
SDK is distinct from the product's TypeScript SDK. Smartcard research is
retired. Historical architecture pages are not current release promises.

The [current requirements](https://github.com/nSealr/nsealr/tree/main/docs/product)
and [task graph](https://github.com/nSealr/nsealr/blob/main/plan/work-items.json)
define the accepted scope. No device production-security claim is made.
